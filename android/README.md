# Catch Me — Android companion (Kotlin + Jetpack Compose)

Foreground-only companion app: signs in to the seeded account, binds the
preprovisioned wearable with its one-time pairing code, connects to the
wearable over BLE (Nordic-style UART service), queues telemetry records
persistently (Room), uploads them to the FastAPI backend, and relays ACK /
SESSION_STATE / TIME_ANCHOR / interaction state and commands / completion
events back to the wearable.

## Module map

| File | Role |
|---|---|
| `ble/Frame.kt` | Wire framing shared with the firmware (0xA5 header, fragmentation, CRC8, reassembly) |
| `ble/BleLink.kt` | Scanner + GATT client; connects to the OWN wearable by manufacturer-data heartbeat (0xC5 magic + alias) |
| `data/Api.kt` | Minimal OkHttp client for the backend contract |
| `data/QueueDb.kt` | Room upload queue + firmware-record → server-JSON codec |
| `data/AppModel.kt` | Telemetry queue/upload/ACK relay; session/time state; authenticated PIN/Truth/Dare/Skip commands and interaction-state relay |
| `MainActivity.kt` | Compose UI: login, bind, connect, quest start, queue status |

## Protocol notes

- The wearable advertises `[0xC5][deviceId][counter LE16][tokenHash LE16]` in
  manufacturer-specific data; phones connect only to their OWN wearable.
  Direct peer evidence is wearable-to-wearable; this app never acts as a
  proximity proxy (docs/AGENTS.md).
- ACKs to the wearable relay only server-persisted record identities; queue
  rows with holes are never acknowledged.
- Records preserve `(boot_id, sequence)` identity across retries; the server
  deduplicates on that key.
- Interaction relay uses framed types 14–16: phone-to-board phase state
  includes only the signed-in wearer's display code; board commands carry a
  session UUID and stable nonce, and the app ACKs only after the API result.
  The four digit entry stays on the wearable; the phone does not autofill it.
